# Подключение Supabase (синхронизация между устройствами)

Без этих шагов приложение тоже работает — просто данные остаются на одном
устройстве, как раньше в артефакте. Подключение занимает минут десять.

Ключи в репозиторий не коммитятся: локально они лежат в `.env.local`, а сборке
на хостинге передаются переменными окружения (для GitHub Actions — секретами).

## 1. Создать проект

1. Зарегистрируйтесь на [supabase.com](https://supabase.com) (бесплатного тарифа
   хватает с большим запасом) и создайте новый проект.
2. Запомните пароль базы данных — он понадобится только для доступа к самой базе,
   в приложении он не используется.

## 2. Создать таблицу

Откройте **SQL Editor** в панели Supabase и выполните:

```sql
create table if not exists public.planner_kv (
  user_id    uuid        not null references auth.users on delete cascade,
  key        text        not null,
  value      text        not null,
  updated_at timestamptz not null default now(),
  primary key (user_id, key)
);

alter table public.planner_kv enable row level security;

-- Каждый видит и меняет только свои строки. Это единственное, что защищает
-- данные: anon-ключ публичный и лежит в собранном JavaScript.
create policy "planner_kv принадлежит владельцу"
  on public.planner_kv
  for all
  to authenticated
  using (auth.uid() = user_id)
  with check (auth.uid() = user_id);
```

Таблица намеренно устроена как «ключ — значение»: в неё без изменения схемы
ложится и всё состояние планировщика (ключ `planner-state-v5`), и каждый
прикреплённый к домашнему заданию файл (ключи `hwfile-*`).

## 3. Включить вход по паролю

**Authentication → Sign In / Providers → Email**: провайдер Email должен быть
включён. Если не хотите возиться с письмами, выключите там же
*Confirm email* — тогда аккаунт заработает сразу после регистрации.

## 4. Прописать ключи

**Project Settings → API**, оттуда нужны два значения:

- `Project URL` → `VITE_SUPABASE_URL`
- **публичный** ключ → `VITE_SUPABASE_ANON_KEY`. В новых проектах он называется
  `publishable` и начинается с `sb_publishable_`, в старых — `anon public` и
  выглядит как длинная строка с `eyJ...`.

> **Никогда не берите ключ, начинающийся с `sb_secret_` (в старых проектах —
> `service_role`).** Он обходит RLS и даёт полный доступ ко всем данным проекта,
> а собранный JavaScript видит любой, кто открыл страницу. Если такой ключ
> куда-то утёк — отзовите его в том же разделе панели Supabase.

Публичный ключ попадает в сборку — это нормально и так задумано: доступ к
данным ограничивает не он, а политика RLS из шага 2.

Локально: скопируйте `.env.example` в `.env.local` и подставьте их туда — этот
файл в `.gitignore` и в репозиторий не попадёт.

Для GitHub Pages: **Settings → Secrets and variables → Actions → New repository
secret**, добавьте оба секрета с теми же именами; сборка подставит их сама.
Для Vercel или Netlify — те же две переменные в настройках проекта.

## 5. Войти

Откройте приложение, нажмите «Войти для синхронизации» в строке сверху,
зарегистрируйтесь один раз и войдите тем же аккаунтом на телефоне.

## Проверка

```bash
node scripts/check-supabase.mjs
```

Скрипт берёт ключи из `.env.local` и отвечает на четыре вопроса: отзывается ли
проект, включён ли вход по почте, нужно ли подтверждение письмом, создана ли
таблица `planner_kv`. Ничего не меняет.

Два необязательных режима:

- `--write-probe` — пробует записать строку без входа. Если запись прошла,
  таблица открыта всему интернету (RLS не настроен); строка тут же удаляется.
- `--signup почта пароль` — заводит настоящий аккаунт и показывает, выдал ли
  сервер сессию сразу или ждёт подтверждения почты.

## Как это работает

- Любое изменение сначала пишется в `localStorage` — приложение работает без
  интернета и не ждёт сервер.
- Затем та же запись уходит в Supabase с меткой времени.
- При открытии приложения (и при каждом возврате в него) обе копии
  сравниваются по метке времени: более свежая побеждает и подтягивает вторую.

Из этого следует правило: если правили на двух устройствах, пока одно было
офлайн, победит то, где изменение сделано позже. Раздел «Перенос данных между
устройствами» остаётся на месте как аварийный вариант.

## Перенос данных из артефакта

1. В старом артефакте откройте «Перенос данных между устройствами» → «Скопировать».
2. В новом приложении откройте тот же раздел, вставьте текст → «Импортировать».
3. Войдите в аккаунт — импортированные данные уедут в облако при первом сохранении.

Файлы, прикреплённые к домашним заданиям, в этот экспорт не попадают (в нём
только имена и ключи вложений) — их придётся прикрепить заново.
