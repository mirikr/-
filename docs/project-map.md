# Ежедневник обществоведа — карта проекта

Личный планировщик подготовки к экзамену и олимпиаде по обществознанию и истории.
Начинался как единый React-компонент (Claude-артефакт) поверх `window.storage`;
сейчас это самостоятельное веб-приложение (Vite + React), которое ставится на
экран «Домой» и синхронизируется между устройствами через Supabase. Этот файл —
краткая карта проекта, чтобы не восстанавливать контекст решений заново.

## Кто пользователь и зачем это нужно

Ученик лицея КЭО, готовится к главному экзамену и олимпиаде по обществознанию
(право, экономика, политология, социология, философия) + история, срок — около
4 месяцев. Идея приложения — вести учебный дневник и распределять ограниченное
время между сферами по модели КПВ (кривая производственных возможностей) из
экономики: время — дефицитный ресурс, уклон в одну сферу означает недобор в
других.

## Из чего состоит приложение (разделы UI, каждый — сворачиваемая секция)

0. **События** — наверху страницы: крупный отсчёт до ближайшего экзамена или
   этапа олимпиады, под ним остальные с датами. Приоритет («!», «⚡», «⚡⚡⚡»)
   решает, до какого события считается план: берётся самое приоритетное, при
   равенстве — ближайшее. Прошедшие события остаются в списке серым.

1. **КПВ (`Распределение времени`)** — планирование и контроль времени:
   - недельная цель по каждому дню недели (Пн–Вс) в минутах — не одно число на
     неделю, потому что в разные дни доступно разное время;
   - часы в неделю на каждый предмет (`budget.alloc`);
   - проверка «хватит ли времени»: остаток непройденных уроков (по их реальной
     длительности) сравнивается с реальным количеством учебных часов до
     дедлайна (считается по дням, а не усреднённо по неделям);
   - предупреждение об уклоне: если один предмет забирает >40% запланированного
     времени — показывается плашка;
   - парный график (бывший «КПВ-график»): теперь строится не по проценту
     пройденных тем, а по **фактически потраченным часам** из дневника —
     пунктирная линия показывает план (соотношение часов из `budget.alloc`),
     точка — факт. Если отклонение факта от плана по выбранной паре предметов
     ≥15 процентных пунктов — отдельное предупреждение.

2. **Самостоятельное изучение** — предметы, уроки и тетрадь:
   - у каждого предмета две вкладки: `Уроки` и `Тетрадь`;
   - тетрадь — это блоки (названия задаёт пользователь), внутри блока ветки
     (темы), внутри ветки конспект с форматированием и прикреплённые файлы;
   - 5 встроенных предметов (право, экономика, политология, социология,
     философия) с реальными уроками и ссылками на курс «Кружок Вебера»
     (zenclass), плюс история (пустая, без готового списка);
   - пользователь может добавлять свои предметы (`customSubjects`) — они
     полностью на равных с встроенными;
   - у каждого урока: длительность (мин), ссылка (можно добавить/поменять в
     любой момент), отметка «пройдено» и заметки — у каждой заметки короткая
     подпись и затраченное время (они кормят дневник), а внутри раскрывается
     тот же конспект с форматированием и файлами, что и в ветках;
   - отметка урока пройденным и добавление заметки с временем **автоматически**
     создают запись в дневнике занятий (не нужно дублировать вручную).

3. **Лицей КЭО — расписание** — отдельно от самостоятельного изучения:
   - фиксированное расписание с звонками: по дням недели (Пн–Сб, воскресенье
     осознанно исключено), предмет вводится свободным текстом прямо в нужный
     день (без отдельного общего списка предметов лицея — раньше был, убрали
     из-за путаницы с удалением);
   - у каждого урока: время начала/конца, кабинет, преподаватель — всё
     редактируется на месте;
   - у урока есть уровень: база, проф, олимпиадное занятие. Он красит левую
     границу карточки и виден в дневнике рядом с предметом;
   - у каждого предмета лицея своя тетрадь — те же блоки и ветки, список тетрадей
     стоит над сеткой расписания.

4. **Дневник занятий**:
   - календарь на месяц, дни красятся от красного к зелёному по тому, сколько
     часов реально потрачено относительно цели на этот день недели (та самая
     цель по дням недели из блока КПВ);
   - клик по дате → список записей за день + блок «Домашнее задание и дела»:
     кроме заданий по урокам расписания есть раздел «Без привязки к уроку» —
     туда попадают дела с дедлайном, не относящиеся ни к какому предмету;
     подтягивает предметы, которые в этот день недели идут по расписанию лицея,
     позволяет добавить к ним ДЗ с текстом, временем на выполнение, отметкой
     «сделано» и **прикреплёнными файлами** (файлы кодируются в base64 и
     хранятся отдельными ключами `hwfile-*` в том же `window.storage`, чтобы не
     раздувать основной объект);
   - у каждого ДЗ настраивается срок напоминания: за 1 день (по умолчанию),
     «всегда» (пока не отмечено сделанным) или «за N дней» — своё число;
   - наверху приложения — баннер с активными напоминаниями о ДЗ (с пометкой
     «сегодня» / «завтра» / «просрочено» / «через N дн.»).

5. **Перенос данных между устройствами** — ручной экспорт/импорт JSON текстом
   (см. ниже, почему это появилось).

## Модель данных (значение под ключом `planner-state-v5`)

```
{
  data: { [subjectId]: { topics: [...], custom: [...] } },   // уроки по предметам
  journal: [{ id, date, subjectId, hours, note, auto, lessonId?, noteId? }],
  budget: { daily: { mon..sun: минуты }, alloc: { [subjectId]: часы/нед } },
  events: [{ id, name, date, priority: 1 | 2 | 3 }],
  notebooks: { [ownerKey]: [{ id, title, branches: [{ id, title, html, files }] }] },
  customSubjects: [{ id, name, color }],
  lyceumSchedule: [{ id, day, subjectName, level, start, end, room, teacher }],
  openSections: { kpv, subjects, lyceum, journal, backup: bool },
  homework: [{ id, date, subjectName, text, minutes, done, attachments: [{name,key}], reminderDays }]
}
```

Каждый урок (в `data[subjectId].topics/custom`):
`{ id, name, url, done, duration, notes: [{ id, text, minutes, date, html, files }] }`.

`ownerKey` тетради — это `subj:<id предмета>` для самостоятельного изучения и
`lyceum:<название предмета>` для лицея. Тетрадь лицея привязана к названию
предмета, а не к конкретному уроку в сетке: один и тот же предмет идёт несколько
раз в неделю, а конспект у него общий.

Вложение — это либо `{ name, size, path }` (файл в Supabase Storage, бакет
`attachments`, папка `<user_id>/…`), либо `{ name, key }` (база64 в
`planner_kv`). Второй формат остаётся навсегда: так читаются вложения, сделанные
до появления бакета, и так работает прикрепление без входа в аккаунт.

**Важно:** ключ хранения (`STORAGE_KEY`) нельзя менять — это единственное, что
связывает пользователя с его старыми данными. Все новые поля добавлялись как
опциональные, со значениями по умолчанию при отсутствии — старые сохранения не
ломаются при обновлении кода.

Само значение — это JSON-строка, которая лежит одновременно в `localStorage`
(ключ `planner:planner-state-v5`) и в таблице `planner_kv` в Supabase. Вложения
к домашним заданиям хранятся там же отдельными ключами `hwfile-*`, чтобы не
раздувать основной объект.

## Как устроено хранение сейчас

`src/storage.js` — тонкий слой «ключ — значение» с двумя копиями данных:

- **`localStorage`** — источник правды на устройстве. Запись синхронная, поэтому
  приложение работает офлайн и не ждёт сеть.
- **Supabase (таблица `planner_kv`)** — общая копия для всех устройств. Пишется
  следом за локальной, с меткой времени `updated_at`.

При чтении обе копии сравниваются по метке времени: свежая побеждает и
подтягивает отставшую. Отсюда правило разрешения конфликтов — выигрывает то
устройство, где правка сделана позже. Настройка описана в
`docs/supabase-setup.md`.

Без переменных окружения Supabase приложение собирается и работает, просто
остаётся локальным — облачная часть отключается целиком.

### Почему ушли от `window.storage`

`window.storage` — служебное хранилище Claude-артефактов, формально «личное для
пользователя», но синхронизация между ноутбуком и iPhone оказалась ненадёжной:
на телефоне чтение стабильно падало с `Storage get failed: unexpected response
type`. Это и стало причиной переезда. Защитные механизмы, выросшие из той
истории, остались в коде и полезны и сейчас:

- дебаунс (700 мс) и до 3 повторных попыток на запись;
- автоподгрузка при возврате в приложение (`visibilitychange`/`focus`),
  плюс перечитывание при входе и выходе из аккаунта;
- кнопка «Обновить сейчас» с временем последней синхронизации и текстом ошибки;
- **ручной экспорт/импорт** (раздел «Перенос данных между устройствами») —
  аварийный вариант, не зависящий ни от какого API.

## Куда двигаться дальше

- **Push-уведомления о домашних заданиях.** Сейчас напоминания — это баннер
  наверху приложения, то есть их видно, только когда приложение открыто. Web
  Push на iOS работает с 16.4+ и только для приложения, добавленного на экран
  «Домой»; понадобится серверная часть (например, Supabase Edge Function по
  расписанию) и хранение подписки устройства.
- **История.** Предмет заведён, но список уроков пустой — заполняется вручную
  по мере появления материалов.
- **Разбить `study-planner.jsx`.** Файл на ~2000 строк удобен, пока правки
  редкие; если разделов станет больше, первым делом стоит вынести дневник и
  расписание в отдельные компоненты.
- **Expo (React Native)** — если понадобится именно нативное приложение. Весь
  UI придётся переписать на `View`/`Text`, а для публикации и push-уведомлений
  нужен аккаунт Apple Developer (99$/год); бизнес-логика при этом переносится
  почти без изменений.
